# Поисковая тулза nspd.gov.ru

`nspd_search_tool.py` - локальный инструмент для поиска объектов на портале
пространственных данных НСПД:

```text
https://nspd.gov.ru/
```

В отличие от `sniprf`, `cntd`, `kontur` и `economy_fgis_tp`, эта тулза ищет не
нормативные документы, а пространственные объекты: земельные участки, здания,
кадастровые кварталы, зоны и территории. Контракт оставлен похожим: функция
возвращает JSON-строку с массивом `documents`, диагностикой `page_reports` и
пачками через `iteration_count`/`limit`.

Скрипт не оценивает, насколько объект подходит по смыслу. Это делает нейронка.

## Почему сайт не открывается в браузере

На скриншоте видно ошибку:

```text
NET::ERR_CERT_AUTHORITY_INVALID
Issuer: Russian Trusted Sub CA
Subject: *.nspd.gov.ru
```

Это значит, что сайт использует российскую цепочку сертификатов, которой
обычная установка Chrome/Python может не доверять. Для скрипта это проявляется
как `SSLCertVerificationError`.

Вторая проблема: системный proxy может возвращать `502 Bad Gateway`.
Поэтому в тулзе сделано так:

- `HTTP.trust_env = False` - не использовать proxy из окружения;
- `verify_tls=False` по умолчанию - отключить проверку TLS только для запросов
  этой тулзы;
- есть отдельная функция `diagnose_nspd_connection()`, которая показывает три
  режима: системный proxy + TLS, прямое подключение + TLS, прямое подключение
  без TLS-проверки.

## Файлы

- `nspd_search_tool.py` - основной поисковый скрипт.
- `nspd_last_result.json` - последний результат ручного тестового запуска.
- `requirements.txt` - зависимости для этой тулзы.

## Установка

Запускать из корня репозитория:

```powershell
pip install -r requirements.txt
pip install -r tools\nspd\requirements.txt
```

## Запуск ручных тестов

Из корня репозитория:

```powershell
python .\tools\nspd\nspd_search_tool.py
```

Команда запускает:

- диагностику подключения;
- позитивные проверки по участку, кварталу и зданию;
- граничные проверки пустого запроса, неправильной итерации, огромной итерации
  и маленького `limit`;
- сохранение результата в `tools\nspd\nspd_last_result.json`.

Последний проверенный запуск:

- `exit_code=0`;
- длительность около `22.5` сек;
- лог: `tools\_test_logs\nspd_run.log`;
- итоговый JSON: `tools\nspd\nspd_last_result.json`;
- диагностика подтвердила: proxy дает `502`, обычная TLS-проверка падает на
  сертификате, прямое подключение с `verify_tls=False` получает `200 OK`.

## Главная функция

```python
from tools.nspd.nspd_search_tool import search_documents_for_construction

raw_json = search_documents_for_construction(
    search_query="03:01:320101:8",
    iteration_count=1,
    max_pages=4,
    limit=5,
    thematic_search_ids=[1, 2, 5, 7],
    include_full_geometry=False,
    verify_tls=False,
)
```

Функция возвращает JSON-строку, а не Python-словарь.

Параметры:

- `search_query` - кадастровый номер или текстовый запрос.
- `iteration_count` - номер пачки результатов, начиная с `1`.
- `max_pages` - сколько тематических поисков проверить.
- `limit` - сколько объектов вернуть за один вызов, обычно `5`.
- `thematic_search_ids` - явный список тематических поисков НСПД.
- `include_full_geometry` - добавлять полную геометрию GeoJSON в ответ.
- `verify_tls` - включить/выключить проверку TLS. По умолчанию `False`.
- `min_score`, `include_text`, `include_full_text` - параметры совместимости с
  остальными тулзами; для НСПД не используются.

## Тематические поиски

Используются открытые REST-запросы НСПД:

```text
https://nspd.gov.ru/api/geoportal/v2/search/geoportal?thematicSearchId=<id>&query=<query>
```

Важно: порядок параметров должен быть именно `thematicSearchId`, потом `query`.
При обратном порядке WAF НСПД иногда возвращает `403 Forbidden`.

Поддерживаемые ID в тулзе:

- `1` - земельные участки, объекты капитального строительства, помещения.
- `2` - единицы кадастрового деления.
- `5` - ЗОУИТ, природные и иные территории.
- `7` - территориальные зоны.

## Пачки по 5 объектов

Логика такая же, как в других тулзах:

1. Первый вызов: `iteration_count=1`, `limit=5`.
2. Нейронка смотрит массив `documents`.
3. Если информации недостаточно и `has_more_documents=true`, вызывается
   `iteration_count=2`.
4. Потом `iteration_count=3` и так далее.

Скрипт не ранжирует и не отбрасывает объекты по смысловому score.

## Структура JSON

Главные поля:

- `status` - `success` или `error`.
- `query` - исходный запрос.
- `documents` - текущая пачка объектов.
- `total_candidates_found` - сколько объектов собрано до нарезки на пачки.
- `documents_returned` - сколько объектов вернул текущий вызов.
- `has_more_documents` - есть ли следующая пачка.
- `page_reports` - диагностика по каждому тематическому запросу.

У каждого объекта:

- `title` - человекочитаемый заголовок.
- `document_type` / `category_name` - категория объекта НСПД.
- `cadastral_number` - кадастровый номер, если есть.
- `address` - адрес, если есть.
- `properties_preview` - важные атрибуты объекта.
- `geometry_summary` - тип геометрии, CRS, bbox и первые координаты.

## Известные ограничения

- Сайт может отдавать `403 Forbidden` на отдельные тематические запросы. Это
  не падение скрипта: ошибка попадет в `page_reports`.
- Поиск по кварталу может возвращать ограниченное количество объектов.
- Полная геометрия может быть большой, поэтому по умолчанию возвращается только
  краткое `geometry_summary`.
